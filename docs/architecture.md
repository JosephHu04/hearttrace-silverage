# 总体架构

## 模块边界

| 模块 | 责任 |
| --- | --- |
| `apps/elder` | 适老陪伴、心情记录、筛查、一键呼救和微信视频联络交接 |
| `apps/family` | 授权后的关怀摘要、趋势、风险与紧急事件行动 |
| `apps/admin` | 关系、授权、风险、设备事件和审计复核 |
| `services/api` | 认证、关系、授权、会话、量表、风险、通知、审计 |
| `services/worker` | 会话后分析、每日汇总、通知和重试 |
| `services/device-gateway` | 设备注册、心跳、求助和跌倒候选事件接入 |

## 关键原则

- 陪伴 Agent 与关怀分析 Agent 是两个独立职责，不等于必须部署两套模型权重。
- 风险等级由规则、量表和趋势融合；模型只提供候选信号与结构化摘要。
- 一键呼救创建服务端事件，再触发通知与人工确认；不能只做前端动画。
- 微信视频仅负责把老人交接至绑定联系人。具体拉起能力以目标 Android 设备与微信公开能力验证为准，并保留电话/联系人页面降级路径。
- 防跌倒优先在设备端处理。日常不允许人工实时观看；摄像头必须可见、可关闭，事件片段须经独立授权并限时保存。

## 推荐技术组合

- 前端：Next.js PWA，三个独立应用或路由组。
- 后端：FastAPI 模块化单体。
- 异步：Redis 加 Arq、RQ 或 Celery。
- 数据：PostgreSQL、pgvector 与受控对象存储。
- 硬件后续路线：Android 触控一体机或平板、实体求助键、端侧跌倒候选检测。

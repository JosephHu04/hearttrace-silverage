# 三端闭环加固与验收说明（2026-09-16）

## 本轮范围

沿用三个独立前端、统一 API、统一业务数据库。修改在 `chore/three-client-integration` 分支，PR #20，不直接提交 main。

### 老人端

- 从演示身份改为本人账号密码登录，验证老人角色及会话有效期。
- 管理员先开通老人账号，再由家属提交注册申请、管理员核验关系并批准绑定。
- 聊天断线可重新连接；登录过期返回登录页；重复呼救重试沿用幂等键。
- 撤回本次会话的分析授权后停止后续存储/分析，模型返回与人工发布前再次校验授权。
- 撤回不等于删除历史数据，也不自动撤销已经单独建立的家属关系授权。

### 家属端

- 新老人没有摘要时返回正常空状态，不再 404。
- 区分等待分析、等待复核、分析失败、分析授权撤回、今日已发布和历史最新摘要。
- 删除固定风险颜色换算的“健康分数”和“个人基线变化”；未实施正式量表时数值为 null。
- 登录限制家属角色；修改密码成功清除旧登录状态。
- 幂等行动重放也必须重新检查有效授权。

### 管理端与后台

- 注册审核区新增老人开户入口、后台任务概览与失败任务人工重试入口。
- 注册审核使用条件更新，避免两名管理员同时通过造成重复开户。
- 普通日常关怀也进入人工复核队列，绿色记录通过解决流程发布摘要。
- 后续新证据递增事件版本；紧急证据提高处理优先级；一般证据不降低现有优先级。
- 恢复超过重试次数且租约过期的卡住任务，失败原因不持久化原始敏感对话。
- WebSocket 每次收到消息重新检查登录凭据。
- Worker 在数据库引擎初始化前加载环境；API、分析和通知支持统一启动。

## 数据库与部署

PostgreSQL 实库测试发现新家属与新老人组合编号超过审计字段原先的 64 字符限制。迁移 `20260916_0011` 将审计目标字段扩至 160 字符，保持完整编号，避免正式数据库下审批失败。

迁移 `20260916_0010` 将 daily_insights 的 score / baseline_delta 改为可空，并清除旧的演示/固定映射分数。不是删除聊天、用户或审核记录。此迁移不伪造分数以支持降级；回滚应使用升级前备份。

已有数据库先备份，再执行（services/api 目录，使用正确 DATABASE_URL）：

```sh
.venv/bin/alembic upgrade head
.venv/bin/alembic check
```

API 和两个任务服务一起启动（仓库根目录）：

```sh
services/api/.venv/bin/python services/worker/run_services.py --api-port 8010 --env-file /absolute/path/to/local.env
```

环境至少包含同一 DATABASE_URL、独立 JWT_SECRET、DASHSCOPE_API_KEY 和三个前端 CORS_ORIGINS。不要将密钥提交 Git。`--check` 只检查配置，不代表模型连通性或评测准确率通过。

`infra/compose.yaml` 提供 PostgreSQL 16、数据库迁移、API、分析及通知服务。数据库不暴露外部端口，API 默认只监听主机回环。生产环境禁止演示登录/种子数据，启动时必须匹配数据库迁移版本。首次管理员用 `docker compose -f infra/compose.yaml exec api python -m app.provision_admin` 交互创建。

部署用数据库密码请选择 URL 安全的随机值（如随机十六进制字符串），JWT 密钥至少 32 字符。Compose 不包含前端部署、域名、HTTPS、短信服务、自动备份任务；不可直接视作完整生产上线方案。

## 验证范围

- 自动化覆盖：全新老人开户 → 密码登录 → 家属申请/批准/绑定 → 授权聊天 → 分析 → 人工复核 → 摘要 → 家属联系 → 通知/审计 → 授权撤回及越权拒绝。
- 覆盖日常摘要发布、紧急证据合并版本、撤回期间模型返回、发布拦截、过期任务恢复与重试权限。
- CI 新增 PostgreSQL 实库测试、并发注册审核、迁移一致性检查和 Compose 配置校验。
- 自动化分析采用合成输出，验证流程与数据一致性，不证明真实模型的心理风险识别准确率。

## 仍需完成，不能宣传为已上线

1. 真正的视频通话未接通；“安排视频”只是关怀行动记录，不是呼起微信视频。
2. 标准化问卷正式施测、解释与专业人员业务流程尚未完成，聊天分析不是诊断。
3. 短信/邮件密码找回没有供应商，接口诚实返回暂未开通；老人初始密码的自助修改界面还需补齐。
4. 无风险事件时不能用风险行动按钮登记联系，可先通过独立关怀计划记录安排；需要另设通用联系日志。
5. 外部电话/短信呼救通知、值班与响应时效保障未接入；站内通知不等于紧急救援送达。
6. 数据保留期限、本人导出/删除申请、家属关系证明及授权凭证、自动备份与恢复演练需确定正式制度。
7. 硬件、摄像头防跌倒、设备离线报警尚未完成。
8. 需要独立样本集与专业复核评估模型误报/漏报；模型服务中断、压力测试、HTTPS 等生产验收仍需推进。

结论：本轮补强核心业务闭环和故障恢复，不代表所有计划功能或生产安全已经验收完成。

# 老年心理与安全筛查标准（MVP）

## 1. 采用原则

本项目采用“多维、分层、可升级”的筛查框架，而不是用一张表或一次大模型分析来判断老人是否患病。

- **每日心情**：用于记录老人自述的当下感受和变化趋势，不是诊断，也不产生疾病分数。
- **标准量表**：采用固定题目、固定计分和版本化模板；由服务端计分，不能由大模型改写或估分。
- **危机安全**：自伤、自杀、明确生命安全危机与一键呼救是独立流程，不与“情绪分”相加后再决定是否处置。
- **人工兜底**：筛查阳性、持续恶化和危机线索均进入人工关怀或专业转介。产品不输出“确诊抑郁症”等结论。

该框架以国家卫健委 WS/T 888—2026《医疗机构老年综合评估技术操作标准》为高层依据。标准要求使用已验证工具、取得知情同意、开展多维度评估，并涵盖认知、抑郁、焦虑和社会支持。

## 2. 工具与产品映射

| 维度 | 首发工具/流程 | 触发与频率 | 产品输出 | 不做什么 |
| --- | --- | --- | --- | --- |
| 当日心情 | 3～5 个大字语音优先的自述问题：心情、睡眠、是否想与人联系 | 每日自愿，允许跳过 | “轻松 / 平静 / 低落”等自述状态和个人趋势 | 不称为量表分数，不推断精神疾病 |
| 抑郁 | PHQ-2 初筛；阳性后由本人完成 PHQ-9 | 初次评估、随访或初筛阳性时；具体周期由专业顾问确认 | “建议进一步关注 / 建议专业咨询”，附量表名称、完成时间和授权状态 | 不显示“已患抑郁症” |
| 焦虑 | GAD-2 初筛；阳性后 GAD-7 | 与抑郁筛查分开记录 | 焦虑关注状态与后续建议 | 不与抑郁合成一个诊断分 |
| 认知 | AD8；阳性后交由医疗或专业人员进一步评估 | 建档、家属观察变化或定期复评 | “建议进一步认知评估” | 不由聊天内容诊断认知障碍 |
| 社会支持 / 孤独 | 采用经专业顾问确认的社会支持评估模板；结合 WS/T 888 引用的社会支持维度 | 建档与阶段性随访 | 联系家属、参与活动等关怀建议 | 不把“独处”自动认定为心理疾病 |
| 自伤 / 自杀风险 | 危机线索触发安全确认；由经过培训的人员使用获授权的 C-SSRS 流程进一步评估 | 任意时刻 | 立即升级、通知和人工处置状态 | 不让模型、家属端或单一总分自动判定风险 |

国家卫健委曾明确提出使用 PHQ-9 开展线上线下抑郁筛查；在老年痴呆防治服务中提出采用 AD8 和简明社区痴呆筛查量表进行认知功能评估。C-SSRS 在国家卫健委《精神障碍诊疗规范（2020 年版）》中被列为自杀风险评估工具。

## 3. 风险与升级规则

### 3.1 大模型的边界

陪伴模型和分析模型仅可输出：`candidate_signal`、`evidence_message_ids`、`confidence`、`recommended_next_step`。它们不能输出诊断、不能直接写入风险等级、不能自动通知家属。

风险引擎必须基于可审计规则，综合以下独立证据：

1. 一键呼救、设备确认跌倒等确定性安全事件；
2. 标准量表的服务端计分结果；
3. 本人连续自述状态、已授权的趋势和人工跟进结果；
4. 模型提供且可追溯到消息 ID 的候选信号。

### 3.2 危机流程

以下任一情况都跳过普通摘要，创建不可被模型关闭的安全事件：老人主动一键呼救；明确的自伤/自杀表达；确认跌倒或其他明确生命安全危机。

1. 老人端立即展示易懂的求助界面与一键呼救选项；
2. 服务端创建红色安全事件并通知已配置的紧急联系人/值守人员；
3. 管理端记录人工确认、联络和升级结果；
4. 仅有在单独授权和必要角色权限下，才可查看受控风险片段；
5. 家属端展示事件状态和下一步，不默认展示完整聊天全文。

危机处理的联系人、响应时限、培训要求和本地紧急服务对接，必须由学校指导教师或合作的心理/医疗专业人员确认后才可上线。

## 4. 数据与授权

### 4.1 量表会话

`screening_sessions` 至少记录：`instrument`、`instrument_version`、`answers`、`score`、`result_band`、`completed_at`、`scored_by=server_rule`、`consent_scope`。

- 题目和计分规则来自版本化模板，不能在客户端硬编码后自行计算。
- 测评答案、原始对话、家属摘要、风险片段和训练用途分别授权。
- 家属默认只看到“是否完成、所属维度、结论级别、建议行动和完成时间”；除非老人单独授权，否则不返回逐题回答。

### 4.2 每日心情

`daily_check_ins` 与正式量表分开保存，至少记录：`mood_label`、`sleep_label`、`connection_preference`、`recorded_at`、`source=self_report`。它只能用于生成“关怀趋势”，不得冒充 PHQ-9、GAD-7 或医疗诊断。

## 5. 跨端职责

| 端 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| 老人端 | 自主完成每日打卡和经同意的标准筛查；查看自己的结果说明；一键呼救 | 被强制答题；被模型告知诊断 |
| 家属端 | 查看被授权的摘要、趋势、筛查完成状态与建议；记录关怀行动 | 修改得分、查看默认原始答案、关闭红色事件 |
| 管理端 | 管理模板版本、授权、人工复核、危机处置与审计 | 用大模型替代专业判断 |
| 后端 | 服务端计分、权限校验、规则融合、审计和通知 | 接受前端提交的“风险等级”作为事实 |

## 6. MVP 验收

1. 每日心情和正式量表在数据库、接口和页面上明确区分。
2. PHQ-9、GAD-7、AD8 模板均有版本号、题目来源记录和服务端评分测试。
3. 模型输出不包含诊断字段，且无法直接修改 `risk_level`。
4. PHQ-9 第 9 题非零、明确危机线索、一键呼救、确认跌倒四种合成场景均能进入人工处置闭环。
5. 无相应授权时，家属接口不返回原始对话、逐题答案或风险片段。

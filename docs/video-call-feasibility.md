# 老人端一键视频联络可行性

## 结论

不建议把产品目标定义为“网页直接唤起某个微信联系人并自动开始微信视频通话”。目前没有查到微信面向普通第三方网页或应用开放的官方接口，能够选择指定个人联系人并替用户发起微信视频电话。依赖非公开 `weixin://` 跳转、模拟点击或无障碍自动操作，不稳定，也有隐私、平台合规和设备适配风险。

比赛版本建议保留“安排视频联络”闭环，但暂不宣称已经打通个人微信视频。真正的一键视频建议采用微信小程序内的自有通话，或直接在专属触控屏与家属网页/App 之间使用 RTC。

## 三种方案对比

| 方案 | 老人体验 | 技术难度 | 稳定性 | 建议 |
| --- | --- | --- | --- | --- |
| 打开微信后由老人手动选家人并点视频 | 两到三步，仍需会用微信 | 低 | 中 | 可作为临时引导，不叫“一键直拨” |
| 微信小程序 + TRTC/TUICallKit | 点击家人头像即可在小程序内呼叫 | 中 | 高 | 若团队确定走微信生态，推荐 |
| 触控屏/Web + TRTC/WebRTC，家属端接听 | 真正产品内一键呼叫 | 中到高 | 高 | 与后续专属硬件最匹配，长期推荐 |

## 推荐架构

```text
老人点击“联系家人”
  -> 后端校验老人—家属授权关系
  -> 创建一次性通话房间和短期令牌
  -> 向家属端发送来电通知
  -> 双方进入 TRTC 房间
  -> 只记录呼叫时间、接听状态和异常原因
  -> 默认不录音、不录像、不保存画面
```

后端需要增加 `call_sessions`、一次性房间令牌、来电超时、拒接/未接状态、重复点击幂等和审计日志。摄像头、麦克风必须由用户主动授权；无人接听时显示“大字重试/联系其他家人/紧急求助”，但普通视频未接不能自动升级为紧急事件。

## 微信小程序限制

- 微信小程序音视频通常基于 `<live-pusher>`、`<live-player>` 与 TRTC SDK，而不是调用微信个人聊天的视频电话。
- 需要常规小程序账号，测试号不具备相关原生组件权限；开发工具不能完整替代真机测试。
- 腾讯云当前将小程序音视频能力与 TRTC 套餐、SDK权限和平台版本要求绑定，正式开发前需要再次核对资质与价格。

## 比赛阶段最小实现

1. 家属端“安排视频联络”继续记录关怀动作和预计时间。
2. 老人端增加“联系家人”入口时，比赛演示先进入本系统的模拟来电确认页，不伪装为已经调用微信。
3. 技术报告展示上述正式架构、权限边界、未接升级策略和真机 PoC 计划。
4. 主线筛查、风险复核和隐私闭环稳定后，再用两个测试微信号和真机完成小程序 TRTC PoC。

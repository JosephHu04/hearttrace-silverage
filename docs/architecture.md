# 总体架构

## 模块边界

| 模块 | 责任 |
| --- | --- |
| `apps/elder` | 适老陪伴、心情记录、筛查、一键呼救和微信视频联络交接 |
| `apps/family` | 授权后的关怀摘要、趋势、风险与紧急事件行动 |
| `apps/admin` | 关系、授权、风险、设备事件和审计复核 |
| `services/api` | 认证、关系、授权、会话、量表、风险、通知、审计 |
| `services/worker` | 会话后分析、每日汇总、通知和重试 |
| `services/device-gateway` | 设备注册、心跳、求助和跌倒候选事件接入 |

## 关键原则

- 陪伴 Agent 与关怀分析 Agent 是两个独立职责，不等于必须部署两套模型权重。
- 风险等级由规则、量表和趋势融合；模型只提供候选信号与结构化摘要。
- 一键呼救创建服务端事件，再触发通知与人工确认；不能只做前端动画。
- 微信视频仅负责把老人交接至绑定联系人。具体拉起能力以目标 Android 设备与微信公开能力验证为准，并保留电话/联系人页面降级路径。
- 防跌倒优先在设备端处理。日常不允许人工实时观看；摄像头必须可见、可关闭，事件片段须经独立授权并限时保存。

## 推荐技术组合

- 前端：Next.js PWA，三个独立应用或路由组。
- 后端：FastAPI 模块化单体。
- 异步：Redis 加 Arq、RQ 或 Celery。
- 数据：PostgreSQL、pgvector 与受控对象存储。
- 硬件后续路线：Android 触控一体机或平板、实体求助键、端侧跌倒候选检测。

## 老人端陪伴纵向切片

```text
apps/elder（Next.js，默认 3002）
  ├─ POST /api/conversations/sessions：声明保存与分析授权
  ├─ WS /api/realtime/conversation：首帧鉴权、流式对话
  └─ GET /api/elder/widgets/*：天气与资讯卡片
                         ↓
services/api
  ├─ 老人角色与会话所有权校验
  ├─ 危机、跌倒和急症确定性安全路由
  ├─ 时间/天气/资讯低延迟路由
  └─ qwen3.8-flash 非思考流式陪伴
```

实时连接只在内存中保留当前会话上下文。只有老人创建会话时明确设置 `saveMessages=true`，服务端才保存聊天消息；`allowAnalysis` 是独立授权，不能由保存授权推导。家属端和管理端不提供聊天原文读取接口。

## 授权分析闭环

```text
已授权保存的助手回复
  → 同事务写入引用型 Outbox（不含原文）
  → Worker 重新校验保存与分析授权
  → Qwen 生成结构化候选信号（不输出诊断或最终等级）
  → 确定性路由创建待人工复核事件
  → 工作人员确认“要求跟进”
  → 发布授权家属可见的结构化摘要与审计记录
```

模型输出不能自动创建紧急求助事件，也不能绕过人工复核直接对家属发布。管理员看到的证据只有候选信号标签和内部分析引用，不包含对话原文。任务失败最多重试三次；Outbox 锁超时可重新领取，避免进程中断后永久丢失任务。
